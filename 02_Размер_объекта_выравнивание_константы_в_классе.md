22. Каков размер «пустого» объекта?
1 байт, чтобы был адрес, отличный от адресов других объектов
Стандарт требует, чтобы **у каждого объекта был уникальный адрес**. Если бы пустой объект занимал 0 байт, два разных объекта могли бы оказаться по одному и тому же адресу.

**Пустой базовый класс в производном — может занимать 0.**  
Это называется **empty base optimization (EBO)**:
```cpp
class Empty {};
class Derived : public Empty { int x; };
sizeof(Derived);   // 4, а не 5 и не 8 — пустая база «бесплатна»
```

23. Влияют ли методы на размер объекта?
Методы (обычные и статические) на размер объекта не влияют
Виртуальные методы влияют: добавляют один vptr, независимо от их количества
Значения по умолчанию у параметров — это подстановка на этапе компиляции, к объекту отношения не имеют, на размер не влияют

26. Что такое выравнивание и от чего оно зависит? Влияет ли выравнивание на размер класса?
Выравнивание  - это требование размещать объекты и поля по адресам, кратным их `alignof`.
Выравнивание поля зависит от его типа (у `char` — 1, у `int` — обычно 4, у `double` и `int64_t` — 8). Выравнивание класса — это **максимум из выравниваний всех его полей и базовых классов**.

Чтобы каждое поле легло на выровненный адрес, компилятор вставляет **padding** между полями. А чтобы размер объекта был кратен выравниванию класса (нужно для массивов), padding может добавляться и **в конце**.

Важно, что если расположить
```cpp
struct B
{
int32_t a;
int64_t b;
int32_t c;
};
// offset 0: a (4)
// offset 4: padding (4)
// offset 8: b (8)
// offset 16: c (4)
// offset 20: padding (4)
// sizeof = 24
struct С
{
int64_t b;
int32_t a;
int32_t c;
};
// offset 0: b (8)
// offset 8: a (4)
// offset 12: c (4)
// sizeof = 16 — без padding, потому что поля идут по убыванию выравнивания
```
